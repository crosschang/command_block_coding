# 정상 FunctionFile 정의 중 자동 출력 제거 — 2026-11-15

## 관측과 판정 범위

사용자 영상 `2026-11-15 09-36-28.mp4`(53.18초)에서는 게임 복귀 뒤 `ffcheck: 1 info. Execution allowed.`가 먼저 나오고, 수십 초 뒤 나머지 FunctionFile 정의 안내가 이어진다. 해당 영상에서는 `CHUNK_BEGIN`/`DONE` 등 행동팩 실행 결과를 확인하지 못했다. 따라서 이 기록은 큰 파일 수신기 실행 시간이 아니라 시작 시 정의 등록/안내 출력 단계의 지연으로 분류한다.

이 화면만으로 검증 계산 시간과 MakeCode의 native 출력 대기/재개 시간을 정확히 분리할 수는 없다. 기존 정상 정의마다 `reportDefinitionComplete()`가 `previewSay()` → `tellraw`를 호출하고, `Preview.ready()`도 정의 캡처 중 진단 가이드를 실제 출력한다는 소스상 경로를 확인했다. 이 경로는 명령 실행의 ON 조회가 적용되기 전이다. 출력 호출을 제거한 결과가 실게임 지연까지 없앴다고 아직 판정하지 않는다.

## 변경

- 정상 정의(OK/WARNING/INFO)는 기존대로 검증·캡처·진단 저장·채팅 등록하되, 완료 안내를 자동으로 게임에 보내지 않는다.
- ERROR/구조 오류의 차단 안내와 실행 금지는 유지한다.
- 상세 진단은 기존 `?`, `함수이름?`로 요청할 수 있다. 경고/정보를 삭제하거나 PASS로 바꾼 것이 아니다.
- 수동 PREVIEW READY 블록은 유지한다. `Command.say("MCFunction Preview Ready")`가 FunctionFile에 캡처되어 해당 함수 실행 시 출력된다.
- PREVIEW READY를 정의하는 것만으로 진단 가이드를 출력하던 부수 동작을 제거한다.
- 분할 송수신·동적 입력 고정·실행 단계 ON·66명령 시험은 변경하지 않는다.
- 행동팩 교체 불필요: 0.0.6 유지. 사용자 시험본은 `CHUNK_FUNCTIONFILES_BLOCKS_V2_MAIN.ts`를 그대로 사용한다.
- 실제 pxt.json 0.0.17을 확인하고 변경하지 않았다. 새 런타임 파일이나 pxt.json.files 등록 변경은 없다.

## 실게임 재확인

Extension을 이번 변경으로 갱신하고 기존 BLOCKS V2 시험본·0.0.6 팩을 유지한다. 게임으로 복귀하면 정상 함수마다 OK/INFO가 자동 출력되지 않는 것이 새 동작이다.

1. `ffping` 한 번 → `FF_CHAT_OK` 확인.
2. `ffready` 한 번 → Ready 및 ACK 결과 확인.
3. 둘 다 응답하면 기존 `ffreset → ffflow → ffcheck`를 각 결과 후 순서대로 확인.

무응답이면 입력을 반복하지 않고 해당 시점의 게임 화면을 보존한다. 위 수정은 시작 중 불필요한 native 출력 경로를 제거한 것이며, 모든 지연의 원인을 해결했다고 주장하지 않는다.
