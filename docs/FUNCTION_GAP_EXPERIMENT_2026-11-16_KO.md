# 진단 출력 없는 분할 전송 대기 비교

## 근거와 범위

비교 영상(사용자 입력을 화면에서 확인한 시각 기준, 약 1초 오차):

| 영상 | 조건 | 관찰 |
|---|---|---|
| 2026-11-16 20-06-06.mp4 | traceon 뒤 첫 ff26 | 약 5초 내 STEP_26, DONE, ACK_DONE, FINISHED. q834185_1 |
| 같은 영상 | traceoff 뒤 두 번째 ff26 | 영상 끝까지 약 95초간 새 완료 응답 없음. ffwhere/traceon 입력 뒤에도 새 응답 미관찰 |
| 2026-11-16 20-09-03.mp4 | traceoff 뒤 ff26 | 약 25초 후 STEP_26, DONE, ACK_DONE. q154951_1 |

두 번째 영상의 traceon은 입력창 작성만 보이며 전송 기록은 보이지 않는다. OFF로 판독한다.
화면 무응답은 즉시 실행 실패로 판정하지 않는다. 진단 출력의 추가 명령과 실행 간격 중 무엇이 영향을 주는지 미확정이다.

## 이번 실험

기존 설정형 진단은 OFF. 기존 ON(GameTime 조회) 6회는 그대로 유지한다.
추가 대기만 0ms / 1ms / 100ms 중 선택한다. 기본값 0ms로 기존 사용자의 동작은 유지한다.
1ms는 API에 요청하는 시간이며 실제 게임에서 정확히 1ms 대기한다는 보장이 아니다.

- 대기 위치: 기존 시간 조회 전후, sendChunkFrame의 native player.execute 전후.
- 현재 26명령의 경우 native 준비 4회 + BEGIN 1회 + PART 18회 + COMMIT 1회 = 24회.
- 추가 대기 위치 총 60곳 = 24*2 + 6*2. 100ms이면 요청상 최소 약 6초를 더한다. 게임 처리 지연은 별도다.
- 최초 읽기 보정 내부의 개별 네이티브 호출, 함수 검색/호출 펼침/컴파일에는 추가 대기를 넣지 않는다. 이 구간 정체는 이번 방법으로 해결하지 못할 수 있다.
- 작성 명령은 기존 AST → Validator → Compiler 경로를 사용한다. 모든 명령 문자열을 고정한 후 첫 추가 대기를 한다.
- 추가 대기 설정도 요청 시작 시 고정한다. 진행 중 변경 요청은 무시한다.
- 프레임 내용/순서/개수/요청 분리/ACK/제한/재전송 정책은 변경하지 않는다.
- trace를 켜서 사용하는 기존 진단 모드의 타이밍 영향은 별도다. 이번 fixture에서는 trace를 켜지 않는다.

## 적용

1. 최신 master의 확장 소스를 적용한다. 시험 파일만 복사하면 신규 설정 API가 없어 컴파일되지 않는다.
2. tests/SMOKE_FUNCTION_GAP_MAIN.ts를 사용자 JavaScript 전체에 붙여넣는다. Extension main.ts에 덮어쓰지 않는다. 내부 API 시험이므로 블록 변환은 하지 않는다.
3. 행동팩 0.0.6을 유지한다. 교체·추가 팩이나 목표 생성은 필요 없다.
4. 함수 정의 ff26 OK가 나온 뒤, 일반 채팅으로 아래 순서를 녹화한다. 시험 중 C/코드 교체/재접속은 하지 않는다.

| 순서 | 채팅 | 다음 단계 조건 |
|---|---|---|
| 1 | ffgap 100 | 새 STEP_26, DONE, ACK_DONE, FF_GAP_RETURN ms=100 found=true ack=2 |
| 2 | ffgap 1 | 새 STEP_26, DONE, ACK_DONE, FF_GAP_RETURN ms=1 found=true ack=2 |
| 3 | ffgap 0 | 새 STEP_26, DONE, ACK_DONE, FF_GAP_RETURN ms=0 found=true ack=2 |

60초 동안 완료되지 않거나 오류가 나오면 다음 시험을 진행하지 않는다. 같은 명령 반복 입력 없이 화면을 보존한다.
시험 명령의 인수 설정 확인은 완료 뒤 FF_GAP_RETURN에서 한다. 실행 전 별도 안내 채팅을 넣어 전송 타이밍을 바꾸지 않는다.
초기 상태 비교가 필요하면 이후 별도 시행에서 순서를 바꿔 확인해야 한다. 이번 한 순서만으로 효과를 확정하지 않는다.

## 검증

- TypeScript 5.9.3 ES5 + 실제 0.0.6 로컬 수신기/모의 월드: 0/1/100ms 모두 동일 26명령과 20개 전송 프레임, ACK2, ON 조회 6회 확인.
- 추가 대기 0/60/60회 확인. TRACE 출력 없음. 잘못된 설정 거부, 진행 중 설정 변경 무시 확인.
- 첫 추가 대기에서 원본 AST를 변조해도 이미 고정된 명령 FROZEN 실행. 불완전 전송 시 실행 0 및 COMMIT 미전송 확인.
- 기존 통합 회귀 검사 통과: 로컬 함수/중첩 execute, 점수, ACK2/9, 입력 고정과 재진입, 큰 요청/긴 명령, 미완성 전송 등.
- 공개 Microsoft Minecraft target 2.2.10 / PXT 13.2.19: 새 사용자 프로그램 포함 컴파일 성공, 진단 0. Education 내장 버전 동일성은 미확인.
- 실제 게임에서 지연이 예방되는지는 미검증. 로컬 모의 대기는 게임의 비동기 처리 시간을 재현하지 않는다.
