# Validation Registry UX - 2026-10-09

## Version

- `0.0.32`

## Definition Validation messages

`FunctionFile.define()` now reports a visible Preview check lifecycle before a chat command is registered:

1. check started
2. ERROR / WARNING / INFO issues
3. check complete summary
4. chat command registration only when there is no ERROR

Preview messages use the existing `tellraw/rawtext` output adapter. They do not use `Command.say()`.

## Registry ID policy

Current Bedrock Registry membership is checked during Definition Validation for supported Block, Entity, and Item positions.

- syntactically broken IDs remain `ERROR` because the command cannot be compiled/executed safely
- `minecraft:*` IDs missing from the current Registry are `WARNING` only
- custom namespace IDs are allowed and reported as `INFO`
- WARNING / INFO never block Preview chat registration or export

The lookup is generated from:

- `registry/source/bedrock/blocks.json`
- `registry/source/bedrock/entities.json`
- `registry/source/bedrock/items.json`

`src/registry/registry_lookup.generated.ts` is generated by `tools/generate_registry.ps1` and must not be edited manually.

## Covered ID positions

- SETBLOCK block
- FILL block and replace filter block
- CLONE filtered block
- GIVE item
- CLEAR item
- SUMMON entity
- Selector `type` entity IDs
- Selector `hasitem` item IDs
- Item component `can_destroy` / `can_place_on` block IDs

Repeated identical issues inside one FunctionFile are de-duplicated before Preview output.
