# 모드3 완료 미확인과 요청 시 상태 조회

## 실게임 기록

- 첫 영상 `2026-11-15 17-42-54.mp4`: MakeCode 전환을 사용자 순서 0→1→4→5→2→3→0으로 나누어 분석했다. 완료 번호 0/1/4/5/2는 영상에서 확인되며, 해당 회차의 게임 복귀부터 첫 완료 표시까지 대략 10/10/9/7/10초였다. 편집·사용자 대기 시간과 이전 회차의 남은 문구를 제외하려고 했다. 이 값은 내부 함수의 순수 실행 시간이 아니다.
- 첫 영상에서 모드3은 약25초 구간에 완료 미확인, 마지막0은 녹화 종료까지 약12초 구간에 완료 미확인이다.
- 추가 영상 `2026-11-15 17-49-50.mp4`: 사용자는 모드3으로 1분 이상 대기한 뒤 0으로 바꿔 종료했다고 보고했다. 영상에서 새 BENCH_READY mode=3은 확인되지 않는다. 화면의 mode0/2 기록과 마지막 전환 뒤 결과를 섞어 0 복귀 시간을 단정하지 않는다.
- 단순히 출력 제외이므로 아무 결과도 없어야 하는 시험이 아니다. 정의별 INFO/OK를 제외해도 공통 BENCH_READY/BENCH_SKIP는 표시해야 한다.
- 현재 판정은 모드3의 장시간 완료 미확인이다. 검사/등록/마지막 결과 출력 중 어디에서 기다리는지는 미확인이다. 출력 제외가 항상 빨라진다거나 반대로 안내가 필수라고 단정하지 않는다.

## 상태 조회 추가

같은 전체 비교를 반복하기 전에, 기본 등록된 `?` 명령으로 현재 메모리 상태를 확인하도록 했다. 새 채팅 명령을 등록하지 않았고, 시작 시 추가 출력·GameTime 조회·pause도 없다.

일반 사용(StartupProbe OFF)에서는 기존 `?` 프로젝트 진단을 유지한다. 전용 병목 시험을 활성화한 경우에만 `?`가 다음 두 줄을 출력한다.

```text
BENCH_STATE mode=3 defs=9 finish=DEFINITIONS last=CHAT_WAIT
BENCH_COUNTS UNIT=CALLS CAPTURE=... CHECK=... STORE=... DIAG=... CHAT=19/20 OUTPUT=...
```

- COUNTS는 반환/진입 횟수다. 예를 들어 CHAT=19/20이면 기록 시점에 등록 호출 하나가 반환되지 않은 상태다. 수치는 밀리초가 아니다.
- finish=DEFINITIONS: finish()에 도달하기 전이다. CHECK/CHAT/DIAG 등 어느 호출이 미반환인지 함께 확인한다.
- finish=READY_SAY_WAIT: 정의 처리 후 첫 공통 완료 문구의 player.say 호출에서 반환을 기다리는 상태다.
- finish=SKIP_SAY_WAIT: 첫 완료 문구 호출은 반환됐고 두 번째 공통 문구 호출이 반환되지 않은 상태다.
- finish=FINISHED: 두 완료 문구 호출까지 코드상 반환됐다. 화면에 표시되지 않는 문제와 코드 진행을 구분하는 단서다.
- last는 마지막 계측 진입/반환 단계다. 중첩 호출을 포함하므로 단독으로 원인을 판단하지 않고 COUNTS와 같이 읽는다.

모드1/4/5는 `?` 자체를 포함한 채팅 등록을 생략하므로 이 조회를 요구하지 않는다. 모드3 또는0에서 사용한다.

상태는 출력 전에 문자열로 확정한다. 다만 질문 이벤트가 지연되어 처리될 수 있고, 상태 출력 자체도 native 호출이다. 따라서 이 기능이 모든 무응답 중간 상태를 반드시 관찰한다고 보증하지 않는다. 조회가 계기가 되어 뒤늦게 진행되는 경우도 별도로 기록해야 한다.

## 다음 시험

Extension만 최신 master로 갱신한다. 기존 전체 병목 시험 TS와 행동팩0.0.6은 그대로 사용한다. 사용자 변경 PXT 버전0.0.18은 보존했다.

1. StartupProbe.begin(3)으로 새로 실행하고 게임으로 복귀한다.
2. 약20~30초 동안 완료 문구가 없으면 일반 채팅으로 `?`를 딱 한 번 입력한다.
3. BENCH_STATE/BENCH_COUNTS와 그 뒤 기존 완료 문구가 나오는지 함께 녹화한다.
4. `?`도 무응답이면 반복 입력하지 말고 그 상태를 추가로 약30초 녹화해 보존한다.

새로운 출력 억제·등록 생략·ON 변경 같은 해결책은 넣지 않았다. 현재 작업은 멈춤 위치를 관측하기 위한 것이다.
